Git & GitHub · Trabajo en equipo

Colaborar es proponer, revisar e integrar.

Guía paso a paso para trabajar en equipo con Git: invitando colaboradores a un repositorio compartido o contribuyendo con un fork. 

$ git switch -c feature/mi-aporte
$ git commit -m "Agrega mi sección"
$ git push -u origin feature/mi-aporte

Paso 0

¿Puedes escribir en el repositorio?

No lo decide el tamaño del proyecto, sino el permiso.

Sí

Repositorio compartido

Todo el equipo tiene permiso de escritura. Cada persona clona, crea ramas y hace push al mismo repositorio.

Típico en empresas y equipos de clase.

No

Fork

Copias el proyecto a tu cuenta, trabajas ahí y propones tus cambios al original con un pull request.

Modelo 1

Repositorio compartido (invitaciones)

  1. El dueño invita

    En GitHub: Settings → Collaborators → Add people. La otra persona acepta en github.com/notifications.

  2. El colaborador clona

    git clone https://github.com/DUEÑO/proyecto.git
cd proyecto

    Descarga el repo completo y crea el remoto origin.

  3. Trabaja en su propia rama

    git switch -c feature/mi-seccion
git add .
git commit -m "Agrega mi sección"
git push -u origin feature/mi-seccion

    -c crea la rama; -u la vincula con la rama remota.

  4. El dueño revisa

    git fetch
git log --oneline main..origin/feature/mi-seccion
git diff main...origin/feature/mi-seccion

    .. = commits nuevos de la rama · ... = cambios desde que se separó de main.

  5. Integra y limpia

    git merge origin/feature/mi-seccion
git push
git push origin --delete feature/mi-seccion

  6. Todos se actualizan

    git switch main
git pull
git fetch --prune
git branch -d feature/mi-seccion
Ojo: en un repo compartido cualquiera puede hacer push a main. Protege la rama en Settings → Branches y usa pull requests.

Modelo 2

Forking workflow

upstream DUEÑO/proyecto Original · solo lectura
Fork →
← PR
origin TU-USUARIO/proyecto Tu copia en GitHub
clone →
← push
tu PC proyecto/ origin + upstream

  1. Haz fork en GitHub

    En el repo original: botón Fork → Create fork.

  2. Clona tu fork y conecta el original

    git clone https://github.com/TU-USUARIO/proyecto.git
cd proyecto
git remote add upstream https://github.com/DUEÑO/proyecto.git
git remote -v

    git remote -v debe mostrar 4 líneas: origin y upstream.

  3. Una rama por cambio

    git switch -c fix/mi-arreglo
git add archivo.html
git commit -m "Corrige el título"
git push -u origin fix/mi-arreglo

  4. Abre el pull request

    En tu fork: Compare & pull request. Comprueba la barra:

    DUEÑO/proyecto main  ←  TU-USUARIO/proyecto fix/mi-arreglo

  5. Mantén tu fork al día

    git switch main
git fetch upstream
git merge upstream/main
git push origin main

    O en GitHub: Sync fork → Update branch y luego git pull.

Truco: si nunca trabajas en main de tu fork, sincronizar siempre es fast-forward: sin conflictos.

Buenas prácticas

🔒 Nada directo a main

Todo cambio entra por una rama y una revisión.

🏷️ Ramas con prefijo

feature/, fix/, docs/ + tu usuario.

🕐 Pull al empezar

git pull antes de trabajar cada día.

✅ Commits pequeños

Un cambio por commit, con mensaje claro en imperativo.

🔍 Otra persona revisa

Nadie integra su propio trabajo sin una segunda mirada.

🧹 Limpia ramas

Borra local y remota cuando ya están integradas.

Si ves esto, no te asustes
